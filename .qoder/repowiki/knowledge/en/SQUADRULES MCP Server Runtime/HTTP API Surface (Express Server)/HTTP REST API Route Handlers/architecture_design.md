Each handler file exports a single `setupXxxRoute(app, ...)` function that registers one or more Express routes; `http-api-routes.ts` is the sole composition point that wires all handlers into the app, passing shared dependencies (`MemoryQdrantStore`, `QdrantService`) per endpoint. Business logic lives outside this module — handlers parse/validate input via Zod schemas from `../tools/*_schema.js` and delegate to pure functions in `../tools/*` (e.g. `executeActivate`, `executeTrain`, `executeReward`, `executeTune`, `executeSpaces`, `executeExport`). Tenant isolation is injected through `runHttpApiWithSpaceContext` / `runWithSpaceContextAsync` from `../utils/tenant-context.js`, which wraps each handler's business call with space-scoped context derived from request headers/query. Error handling is centralized: validation failures return `{ error: 'INVALID_INPUT', message }`; domain errors are caught by `sendToolRouteError` (from `./http-route-errors.js`) or by explicit `instanceof TrainError` / `SquadrulesError` branches that map to typed error codes like `DUPLICATE_ADAPTER`, `SIMILAR_MEMORY_FOUND`, `STORE_FAILED`. The `/api/me` route is auth-only and reads `req.auth` (typed `AuthPayload`) after OIDC middleware, deriving `account_kind`/`account_label` via `oidc-profile-claims.js`. The `/api/train/raw` endpoint additionally uses `raw-body` with `HTTP_TRAIN_RAW_BODY_LIMIT` and sanitizes response detail keys via a whitelist.
