Four focused files form the HTTP boundary of the MCP subsystem:
- `http-mcp-handler.ts` registers `POST /mcp`, creates a fresh `StreamableHTTPServerTransport` + MCP server per request (avoiding single-transport concurrency limits), enforces a process-wide concurrent-request cap via an in-memory counter (503 when exceeded), resolves Bearer tokens through `bearer-validate.js`, injects space/tenant context via `AsyncLocalStorage`, and special-cases `listOfferingsForUI` before SDK dispatch.
- `mcp-audit-emit.ts` is a thin audit facade: it wraps `transport.send()` to capture JSON-RPC responses for level-3 replay, emits `mcp_request_start` / `mcp_request_end` / `mcp_tool_call` events through `writeAuditLine`, and uses `AUDIT_LOG_LEVEL` from config as a gate.
- `mcp-ui-offerings-auth-jsonrpc.ts` builds implementation-defined JSON-RPC errors (-32001) for unauthenticated UI discovery, reusing `safeCreateOidcLoginUrlForApiResponse` so clients can redirect to SSO.
- `http-client-registration-proxy.ts` mounts `/ .well-known/clients-registrations/openid-connect` and forwards POST/GET/PUT/DELETE to Keycloak (`KEYCLOAK_URL` / `KEYCLOAK_INTERNAL_URL` + realm), rewriting `registration_client_uri` and `Location` headers to the public `AUTH_CALLBACK_BASE_URL` so browser-based client registrations resolve against the external hostname.

Dependency direction is one-way outward: this module depends on `../server.js` (MCP server factory), `../utils/*` (logger, tenant-context, concurrency-limit, audit-summary), and auth helpers under `./http-*`; nothing inside `src/http/` imports back into these files. The handler is the only place that wires Express routes; other modules call `setupMcpRoutes` / `setupClientRegistrationProxy` from their app bootstrap.
