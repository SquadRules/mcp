The module is organized around a single entry point `startHttpServer` in `http-server.ts` that composes an Express app by calling per-feature setup functions (`configureMiddleware`, `setupAuthCallback`, `setupWellKnown`, `setupMcpCorsRoutes`, `setupApiRoutes`, `setupMcpRoutes`, `setupUiStatic`, `setupErrorHandlers`) in a strict order — notably `/well-known` and CORS are mounted before auth so MCP clients can discover capabilities unauthenticated. `http-server-config.ts` owns cross-cutting middleware: structured logging, Prometheus metrics, helmet CSP, and per-path `express-rate-limit` buckets (`/auth`, `/api`, `/mcp`) driven by constants from `../config.js`. `http-metrics-middleware.ts` instruments every request with Prometheus counters/histograms keyed by method/route/tenant_id, wrapping `res.send` to capture response size. `http-error-handlers.ts` registers the global 413/500 handler plus a 405 for GET `/mcp` and a catch-all 404. `http-route-errors.ts` provides `sendToolRouteError`, a helper route handlers use to normalize domain errors (`SquadrulesError`) into `{error, message}` JSON responses. `http-server-startup.ts` isolates `app.listen` and converts Node `EADDRINUSE` / other listen errors into structured logs + `process.exit(1)`. Dependency direction is one-way: this layer depends on `../services/*`, `../utils/*`, and `../types/*` but nothing in those layers depends back on it.
