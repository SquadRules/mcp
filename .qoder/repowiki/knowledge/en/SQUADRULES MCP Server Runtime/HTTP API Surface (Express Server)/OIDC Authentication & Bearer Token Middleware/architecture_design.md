Layered around a single `AuthPayload` type (`src/http/bearer-validate.ts`) consumed by both session and Bearer flows:
- Entry point: `http-auth-middleware.ts` is an Express `authMiddleware(req,res,next)` applied to `/api`, `/mcp`, `/ui`. It short-circuits when `AUTH_ENABLED=false`, skips `/auth/callback` and `OPTIONS`, then tries session cookie first; if absent, falls back to Bearer validation via `bearer-validate.ts`; otherwise redirects browsers or returns 401 with `WWW-Authenticate`.
- Session flow: `http-auth-callback.ts` registers `/auth/callback`, exchanges the authorization code for id_token/access_token against Keycloak, merges payloads via `oidc-profile-claims.ts`, signs an HMAC-SHA256 session cookie (`squadrules_session`) using `SESSION_SECRET`, and stores the id_token as `oidc_id_token` for RP-initiated logout.
- Browser redirect: `http-auth-oidc-redirect.ts` builds PKCE authorization URLs, persists state+code_verifier in `oidcStateStore` (Redis-backed), and provides `safeCreateOidcLoginUrlForApiResponse()` for JSON login_url fields.
- Bearer flow: `bearer-validate.ts` uses `jose`'s `jwtVerify` + `createRemoteJWKSet` to verify iss/aud/exp/signature against Keycloak JWKS (with `KEYCLOAK_INTERNAL_URL` remapping for Docker), optionally fetches groups from the userinfo endpoint, and applies the same group allowlist as the session path.
- Shared claim processing: `oidc-profile-claims.ts` centralizes whitelisted profile field extraction, group normalization/allowlisting, realm derivation from issuer, and id/access token merging — used by both callback and bearer paths so they produce identical `AuthPayload` shapes.
- HTTP framing: `http-www-authenticate.ts` builds RFC-compliant `WWW-Authenticate: Bearer ...` headers (including `resource_metadata`, `authorization_uri`, `scope`) so MCP clients can discover the protected-resource metadata and re-authenticate.
- Scopes: `oidc-scopes.ts` declares the default supported scopes (`openid`, `profile`, `email`, `squadrules-groups`, `offline_access`) and parses the `SQUADRULES_OIDC_SCOPES_SUPPORTED` env var.
Dependency direction is one-way: middleware → (callback | redirect | bearer-validate) → oidc-profile-claims; nothing in this module imports from higher layers. The middleware augments Express `Request` with `auth`, `spaceContext`, and `requestId` via a global declaration.
