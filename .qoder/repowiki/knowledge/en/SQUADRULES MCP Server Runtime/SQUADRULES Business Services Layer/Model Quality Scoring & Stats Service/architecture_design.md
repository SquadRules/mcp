The module is organized around a single orchestrator class `ModelStatsService` in `model-stats.ts`, which owns in-memory state (`StatsState`) and persists it through `keyValueStore` (Redis-backed) under keys like `stats:state`, `stats:implementationBonusTotals`, and `stats:rareSuccessCounts`. Pure computation logic is split into sibling files with no internal dependencies on the orchestrator: `scoring.ts` (quality score components — specificity, expert value, broad utility, longevity), `bonuses.ts` (Wilson-adjusted implementation bonus with rarity/comparative multipliers), `healer.ts` (experience-based healer improvement bonus), and `protocol.ts` (workflow-level potential aggregation over Qdrant protocol steps). `types.ts` centralizes shared interfaces (`QualityScore`, `ModelStats`, `RecentDiscovery`, `StatsState`). The orchestrator imports submodules lazily at the top of the file to avoid circular deps and delegates all scoring/bonus calculations to them, while also emitting Prometheus metrics via `agentContributions`, `agentQualityScore`, `agentImplementationBonus`, and `agentRareSuccesses` from `../metrics/agent-metrics.js`. External side effects are isolated: Qdrant access happens only inside `protocol.ts` via dynamic `import('../qdrant/index.js')`, and tenant context is read through `getTenantId()`.
