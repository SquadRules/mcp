Layered around a single `EmbeddingService` class (`service.ts`) that exposes `generateEmbedding`, `generateBatchEmbeddings`, `calculateCosineSimilarity`, and `generateMemoryEmbedding`. Provider dispatch is split into two concerns: `provider-resolver.ts` selects the candidate provider based on `EMBEDDING_PROVIDER` env (explicit preference → auto-detect openai/tei/fastembed) while `providers.ts` holds the HTTP/local transport implementations (`postEmbeddingsOpenAI`, `postEmbeddingsTEI`, `postEmbeddingsFastEmbed`) plus shared retry/backoff logic (`fetchWithRetries`, exponential jitter, `Retry-After` header parsing, wall-clock budget). The fastembed backend (`fastembed-provider.ts`) is loaded lazily via dynamic `import('fastembed')` so ONNX bindings never load unless selected. Dimension resolution is enforced at runtime through `config.ts`'s `setResolvedEmbeddingDimension` / `getResolvedEmbeddingDimension` pair, probed eagerly by `probeEmbeddingDimension()` and memoized for concurrent callers in `lazy-probe.ts`. Observability is split between `audit.ts` (request-level success/error + anomaly detection on latency/norm/dimension) and `provider-audit.ts` (structured per-provider call logs), both emitting to `structuredLogger` with tenant/request context from `utils/tenant-context`. Health checks live in `health.ts` and mirror the provider selection policy. A standalone `bm25-tokenizer.ts` implements an in-process FNV-1a mod-30000 sparse vector tokenizer for Qdrant sparse search, independent of the dense embedding providers.
