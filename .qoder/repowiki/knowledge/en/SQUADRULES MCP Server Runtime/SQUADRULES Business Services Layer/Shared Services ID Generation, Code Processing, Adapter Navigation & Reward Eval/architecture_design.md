Six independent service files under src/services/ with no shared internal sub-packages:
- id-generator.ts exposes a static `IDGenerator` class wrapping uuid v4/v5 and Node's `crypto.randomUUID`, plus the module-level `SQUADRULES_NAMESPACE` UUID used for deterministic URI→Qdrant point mapping via `buildQdrantId` / `qdrantIdFromUri`.
- code-block-processor.ts defines `CodeBlockProcessor` with regex-based extraction of fenced code blocks and language-specific identifier patterns (JS/TS, Python, Java, C#) to enrich search content.
- adapter-layer-count.ts provides pure helpers (`maxLayerIndexFromAdapterPoints`, `effectiveAdapterLayerCount`) that reconcile in-memory `layer_count` against Qdrant payload `layer_index`, trusting Qdrant when stale.
- adapter-navigation.ts implements `resolveAdapterEntry/FirstLayer/NextLayer/PreviousLayer` and `buildAndPinLayerManifest`, walking adapter layers via `qdrantService.getAdapterLayers`; when an `executionId` is supplied it reads/pins a manifest through `forwardRuntimeStore` to prevent UUID churn (#79).
- reward-evals.ts is a pure evaluator: `evaluateReward` computes normalized/signed scores, gold/silver/bronze/rejected labels, and SFT/preference eligibility based on thresholds (MIN_SFT_SCORE=0.65, MIN_PREFERENCE_SCORE=0.7).
- reward-metrics.ts is the only file with I/O side effects: `applyRewardMetrics` calls `qdrantService.retrieveById/updateQualityMetrics/propagateRewardToAdapterHead`, invalidates Redis cache, and delegates bonus/metadata computation to `modelStats`.
Dependency direction is one-way outward: this module consumes qdrant, redis-cache, memory-accessors, forward-runtime-store, model-stats, structured-logger, and types; nothing inside the scope imports from each other except reward-metrics → id-generator.
