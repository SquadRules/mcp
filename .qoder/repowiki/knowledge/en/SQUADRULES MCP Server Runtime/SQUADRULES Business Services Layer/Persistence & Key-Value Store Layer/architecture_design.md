Layered around a single `IKeyValueStore` interface (`key-value-store.ts`) with two backends: `RedisService` (production, via `redis` package) and `MemoryStore` (dev fallback). Backend selection is centralized in `key-value-store-factory.ts`, which exports a singleton `keyValueStore` chosen by `isRedisConfigured`; consumers never import Redis/Memory directly. Domain stores (`oidc-state-store`, `proof-of-work-store`, `forward-runtime-store`, `activate-refinement-store`) are thin wrappers over this shared backend, each owning its own key prefix scheme. `RedisCacheService` sits above the KV layer to provide application-level caching of search results and memory resources, using Redis pub/sub on channel `cache:invalidation` for cross-process invalidation. `ExecutionTraceStore` is orthogonal: it bypasses the KV layer entirely and persists traces to Qdrant (or embedded LanceDB when Qdrant is not configured), exposing the `IExecutionTraceStore` interface so callers remain backend-agnostic. Key namespacing uses `SQUADRULES_REDIS_PREFIX` plus per-space IDs from `getSpaceIdFromStorage()`, except for global prefixes `MEMORY_CACHE_KEY_PREFIX` and `OIDC_STATE_KEY_PREFIX` that intentionally skip space scoping.
