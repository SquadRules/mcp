Single flat module under src/services/metrics/ that owns all Prometheus instrumentation for the application. `registry.ts` is the single entry point: it creates a `@prometheus-io/client` `Registry`, applies default labels (`service='squadrules'`, `squadrules_version` from build metadata, `instance` from `INSTANCE_ID` env or hostname), and exports it so every other file re-imports it via `registers: [register]`. Each domain file (`http-metrics.ts`, `agent-metrics.ts`, `embedding-metrics.ts`, `memory-metrics.ts`, `qdrant-metrics.ts`, `mcp-metrics.ts`, `anomaly-metrics.ts`, `export-metrics.ts`, `system-metrics.ts`) declares its own set of `Counter`/`Histogram`/`Gauge` instances scoped to one subsystem. `system-metrics.ts` additionally boots process-level gauges (uptime, RSS/heap memory, start time) on import using `setInterval` and `process.memoryUsage`. Tenant isolation is enforced by requiring `tenant_id` as an explicit label per metric rather than a default label, as documented in `registry.ts`.
