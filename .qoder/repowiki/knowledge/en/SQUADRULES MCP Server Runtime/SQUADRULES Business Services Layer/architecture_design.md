Children are layered rather than peer microservices: `embedding` produces dense/sparse vectors consumed by `memory`, which persists them via the `qdrant` collection service; `vector-store` provides a backend-neutral port (LanceDB adapter) that `qdrant` falls back to when embedded. `metrics` registers Prometheus counters/gauges across all children under a shared registry with default service labels. `persistence_state` supplies the key-value store abstraction used by `stats`, `export_capability`, and several top-level stores (OIDC state, proof-of-work, forward runtime, execution traces). Top-level files in `src/services/` (e.g. `memory-store.ts`, `key-value-store-factory.ts`, `redis.ts`, `reward-evals.ts`) act as the composition root that wires these children together for callers in `src/tools/` and `src/http/`. Isolation is enforced by explicit TypeScript interfaces (`IVectorRecordStore`, `IExecutionTraceStore`, adapter contracts in `memory/store-adapter-*`) rather than runtime boundaries.
