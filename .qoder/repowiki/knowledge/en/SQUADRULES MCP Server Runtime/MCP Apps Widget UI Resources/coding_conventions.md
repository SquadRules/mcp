- Every widget is registered twice under two URI schemes (`ui://squadrules/*` and `ui://open-ai/squadrules/*`) with corresponding MIME types (`text/html;profile=mcp-app` and `text/html+skybridge`) so both MCP Apps and Skybridge hosts can render it.
- Widget HTML fragments are assembled in `{name}-widget-html.ts` by concatenating a root `<div>`, an inline `<style>` block importing the CSS string export, and an inline `<script>` block wrapping the JS IIFE export through `substituteWidgetPresentationToken` before passing the whole template through `minifyInlineWidgetHtml`.
- UI metadata for each tool is declared as a constant in `squadrules-ui-constants.ts` containing both the nested `{ ui: { resourceUri } }` shape and the flat `'ui/resourceUri'` key, then referenced by the tool's `registerTool` call and the resource registration file.
- Inline scripts follow a vanilla JS IIFE pattern that performs the `ui/initialize` / `ui/notifications/initialized` handshake, handles both `ui/notifications/tool-result` and legacy `notifications/tool-result` method names, and calls `notifySize()` after every render path to let the host resize the iframe.
- Shared visual tokens (colors, typography, dark-mode variables) live in `mcp-widget-chrome-inline-css.ts` and are imported by widget CSS rather than duplicated, keeping the Chrome look consistent across activate, forward, and spaces widgets.
