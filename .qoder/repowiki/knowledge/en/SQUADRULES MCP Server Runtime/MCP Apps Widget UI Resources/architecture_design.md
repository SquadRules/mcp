Each widget follows a fixed three-file layout — `{name}-widget-html.ts` (HTML fragment builder), `{name}-widget-inline-css.ts` (CSS string export), `{name}-widget-inline-script.ts` (vanilla JS IIFE export) — plus a `register-{name}-ui-resources.ts` that calls `server.registerResource()` twice: once with `text/html;profile=mcp-app` on `ui://squadrules/*` and once with `text/html+skybridge` on `ui://open-ai/squadrules/*` to support both MCP Apps hosts (Cursor, Claude Desktop) and Skybridge hosts (ChatGPT, Windsurf). The HTML builder composes `<div>` + `<style>` + `<script>` via template literals, runs them through `minifyInlineWidgetHtml`, and injects the CSS/JS string exports. Shared cross-widget assets live in dedicated files: `squadrules-ui-constants.ts` (URIs, `_meta.ui.resourceUri` bindings, MIME types), `mcp-widget-chrome-inline-css.ts` (shared Chrome tokens/dark mode), `mcp-widget-presentation-inject.ts` (injects `SQUADRULES_MCP_WIDGET_PRESENTATION_ONLY` flag into scripts), `squadrules-logo-embedded.ts` (inline SVG), and `list-offerings-for-ui.ts` (combined tools/resources/prompts listing for UI discovery). Dependency direction is one-way: widget builders → shared constants/chrome CSS/presentation injector; registration modules → widget HTML builders; nothing in this module imports server tool handlers.
