The module is a thin bootstrap layer between the MCP SDK server and three content sources: (1) build-time-embedded docs/prompts/templates in `embedded-mcp-resources.ts` (auto-generated by `scripts/build-embed-docs.ts`), (2) filesystem-backed mem adapter markdown under `src/embed-docs/mem/`, and (3) internal bootstrap placeholders.

- Handler registration: `docs-resources.ts` iterates the embedded `resources` map and calls `server.registerResource` for each doc; `prompt-resources.ts` does the same via `server.registerPrompt`; both use `getResources`/`getPrompts`/`getResource`/`getPrompt` accessors from the generated file. `resource-bootstrap.ts` registers and immediately removes placeholder resources/templates so the SDK exposes `resources/*` and `templates/list` even when no real handlers exist — a workaround for lazy handler installation.
- Mem adapter injection: `mem-resources-boot.ts` is the startup entry point. It reads `.md` files from `embed-docs/mem` (with a fallback dir detection for src/dist builds via `mem-dir-utils.ts`), parses frontmatter + H1 title, compares stored vs shipped semver (`compareSemver`), deletes preexisting app-space entries by slug or derived UUID5 (`mem-uuid-mapper.ts`), re-trains through `MemoryQdrantStore.storeAdapter`, and persists a `content_sha256` payload on layers for later change detection. A `force` option bypasses version checks to support structural repair.
- Dependency direction: this module depends outward on `services/memory/store.js`, `services/redis-cache.js`, `utils/frontmatter.js`, `utils/version-compare.js`, `tools/skill-export/sha256.js`, and `config.js`, but nothing inside `src/resources/` imports from those services except the boot path — the rest are pure registration helpers.
- The `mem-uuid-mapper.ts` also exposes `extractFirstH1Title` / `extractFrontmatterSlug` used by the boot flow to reconcile filename slugs with frontmatter slugs.
