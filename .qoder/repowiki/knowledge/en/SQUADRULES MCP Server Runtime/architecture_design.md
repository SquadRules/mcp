Two-stage entrypoint: `src/bootstrap.ts` installs uncaughtException/unhandledRejection handlers before any app code loads, then dynamically imports `src/index.ts`, which calls `runSquadrulesServer()`. That function runs a fixed boot sequence shared by both CLI and HTTP modes — install global error handlers & signal listeners, print stdio banner, call `bootLocalRuntime()` from `runtime_boot` to select LanceDB/Qdrant, probe embeddings, seed the app space, optionally start the metrics server, then dispatch on `TRANSPORT_TYPE` (from `config/runtime-mode.ts`) to either `startHttpTransport(memoryStore)` or `startStdioTransport(memoryStore)`. The `memoryStore` returned by `bootLocalRuntime` is the single cross-child dependency injected into both transports; all other children (`http_api`, `cli`, `tools`, `services`, `resources`, `embed_docs`, `ui`, `mcp_apps`) are loaded transitively through those transports. Configuration is centralized in `src/config.ts` (env parsing + derived constants like `SERVER_PORT`, `METRICS_PORT`, `OIDC_*`, `AUTH_TRUSTED_ISSUERS`) with runtime-mode overrides re-exported from `./config/runtime-mode.js`; `src/metrics-server.ts` and `src/me-response.ts` provide auxiliary HTTP surfaces only active in http mode. Graceful shutdown uses SIGTERM/SIGINT handlers that force-exit after 1s if open handles (Qdrant gRPC, stdio pipes) keep the event loop alive.
