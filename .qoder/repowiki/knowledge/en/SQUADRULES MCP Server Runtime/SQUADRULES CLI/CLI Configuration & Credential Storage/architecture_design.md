Four-file layering inside `src/cli/`:
- `config-file-internals.ts` is the lowest layer: pure JSON shape (`ConfigFileShape`, `EnvironmentEntry`), path helpers (`getConfigPath`, `getConfigDir` via `squadrules-user-dirs`), parsing/writing, URL normalization, and the `__KEYCHAIN__` sentinel used as a placeholder when secrets live in the OS keyring.
- `config-file.ts` implements the read side: `readConfig(baseUrl?)` resolves per-environment tokens by merging keyring lookups with on-disk values, migrating legacy single-env flat configs into the new multi-environment shape, and writing back placeholders after successful keyring migration. `getDefaultApiUrlFromFile()` is a sync-only helper for non-keyring consumers.
- `config-file-write.ts` implements the write side: `writeConfig(partial)` merges partial updates into the existing file, stores secrets in the keyring when available (falling back to inline file storage with a one-time stderr warning), and replaces inline secrets with `__KEYCHAIN__` sentinels.
- `config.ts` is the public resolution entry point: `getCliApiUrlDefault()` / `getApiUrl()` resolve the effective API URL through the documented precedence chain — Commander `--url` → `SQUADRULES_API_URL` env → saved `defaultUrl` → `LOCAL_TARGET` sentinel — keeping the CLI local-by-default until `login` flips it to HTTP.

Dependency direction is strictly inward: `config.ts` → `config-file.ts` → `config-file-internals.ts`; write/read share internals but never import each other. Secrets are abstracted behind `./keyring.js` so the rest of the module stays keyring-agnostic.
