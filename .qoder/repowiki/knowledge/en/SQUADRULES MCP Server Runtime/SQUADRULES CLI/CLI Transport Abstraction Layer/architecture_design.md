The module defines a transport-agnostic `ActionBackend` interface (`action-backend.ts`) whose methods mirror the tool-layer `execute*` functions and return canonical output shapes from `src/tools/*`. Two implementations exist: `HttpBackend` is a thin passthrough over `ApiClient`, preserving pre-existing HTTP auth/timeout/retry behavior; `LocalBackend` boots an embedded runtime via `bootLocalRuntime` (fastboot defaults, lazy embeddings) and calls the same `execute*` cores under `defaultSpaceContext()` so local and remote results are identical. `resolve-backend.ts` is the factory: it reads the resolved `--url` target, treats the `stdio://local` sentinel as local mode, validates http(s) URLs via `normalizeAndValidateApiBaseUrl`, and dynamically `import()`s `LocalBackend` only for local runs — keeping the heavy embedding stack out of pure HTTP invocations. Dependency direction is one-way: consumers depend on the `ActionBackend` type; backends depend on `ApiClient` (HTTP) or `tools/*` + `runtime/boot-local-runtime` (local), never on each other.
