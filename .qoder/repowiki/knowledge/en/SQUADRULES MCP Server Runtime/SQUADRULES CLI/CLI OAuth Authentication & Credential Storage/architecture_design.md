Four focused utilities under src/cli/ that together implement the CLI's authentication surface:
- auth-error.ts defines AuthRequiredError (carrying a loginUrl) plus openBrowser/handleApiError; it is the single place where 401 responses are turned into user-facing messages and optional browser launches, with BROWSER env gating.
- oauth-refresh.ts exposes fetchOAuthProtectedResourceMetadata + refreshAccessToken, discovering token/auth endpoints from /.well-known/oauth-protected-resource and POSTing a refresh_token grant using the hardcoded SQUADRULES_CLI_CLIENT_ID; jwtExpiresInSeconds parses the JWT exp claim without a library.
- rewrite-login-url.ts rewrites server-provided OIDC login URLs so redirect_uri points at the CLI's --url base instead of AUTH_CALLBACK_BASE_URL, fixing cross-origin callback redirects.
- keyring.ts wraps @napi-rs/keyring via dynamic require, providing getToken/setToken/deleteToken and matching getRefreshToken/setRefreshToken/deleteRefreshToken APIs with a per-account '::refresh' suffix. It implements a degradation latch (keyringDegraded) so a hung macOS Keychain stops blocking subsequent calls, and falls back to XDG config file storage when the native binding is missing or times out.
Dependency direction is one-way: keyring stores tokens produced by oauth-refresh; rewrite-login-url is consumed by the login flow; auth-error is the error boundary for all of them. All network I/O accepts an injectable fetchImpl for testability.
