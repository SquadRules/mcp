Two cooperating sub-trees with a one-way dependency: `src/config/` and `src/constants/` are pure, side-effect-free modules that resolve settings from `process.env`, while `src/runtime/boot-local-runtime.ts` is the only place that performs I/O.

- `runtime/boot-local-runtime.ts` exposes `bootLocalRuntime(opts)` plus `isEmbeddedStoreSeeded()`. It selects the vector store via `isQdrantConfigured` (`MemoryQdrantStore` for external Qdrant, embedded LanceDB singleton otherwise), optionally waits for Qdrant health, probes embedding dimensions, runs width reconciliation against the stored provider/model/dimension, triggers a startup snapshot when configured, and seeds app-space adapters through `injectMemResourcesAtBoot` using a `SeedMode` policy (`always` / `auto` / `never`).
- `config/mem-boot.ts` isolates the `MEM_BOOT_FORCE_INJECT` env switch (the structural-repair hatch) out of the main config file to respect the max-lines budget; it uses a small `getEnvBoolean` helper.
- `config/runtime-mode.ts` defines the two mutually exclusive modes — `simple` (stdio, single-user, embedded LanceDB, no HTTP/auth surface) and `cluster` (http, REST API + Streamable MCP + OIDC + metrics) — and derives `TRANSPORT_TYPE`, `AUTH_ENABLED`, and `isQdrantConfigured` as pure functions over an env record so they can be unit-tested without mutating module-level state. `getStdioConfigViolations` returns human-readable messages (not thrown) so callers in `../config.ts` can turn them into startup errors after Keycloak validation.
- `constants/builtin-search-meta.ts` holds protocol slugs (`refine-search`, `author-adapter`) and footer labels resolved from embedded meta docs via `getMetaDoc` + `parseFrontmatter`, used to filter built-in search-footer memory entries.

Dependency direction: boot → config/* (env resolution) → services/* (vector store, embedding, qdrant); constants/* has no runtime dependencies beyond resource loaders.
