All child tool modules (activate, forward, next, train_tune, export, skill_export, delete_dump_update) are leaf implementations that register themselves against the single `SQUADRULES_TOOL_REGISTRY` in `tool-registry.ts`. Each entry pairs a tool name with its `strictInputSchema`/`outputSchema` Zod schemas (defined in sibling `*_schema.ts` files), a doc string resolved via `resolveToolDoc`, and optional UI metadata. The registry is the cross-cutting contract consumed by MCP `tools/list`, HTTP `/api/<tool>` routes, and CLI commands — so adding a tool requires updating this registry plus its schema file rather than touching server wiring. Shared cross-tool infrastructure lives at the top level of `src/tools/`: `forward-*` helpers for error/trace/view payloads, `next-*` proof-of-work types, `local-artifact-dir-contract`, `train-*-uri`/`train-mime` adapters, and `mcp-tool-input-teaching` for converting validation failures into agent-teaching errors. The `skill_export` pipeline consumes adapter artifacts produced by the other tools to produce SKILL.md bundles, making it an output consumer rather than a registered tool.
