Single-module leaf under `src/tools/` that centralizes three concerns:
- Canonical tool surface: `tool-registry.ts` exports `SQUADRULES_TOOL_REGISTRY`, a `as const` array of `{ name, title, description, strictInputSchema, outputSchema }` entries (activate, forward, train, reward, tune, delete, export, spaces). Each entry pulls its Zod schemas from sibling `*_schema.js` files and resolves human-facing docs via `resolveToolDoc`; UI hints come from `squadrules-ui-constants`. The registry is the single source of truth consumed by MCP `tools/list`, HTTP `/api/<tool>` routes, and CLI commands.
- Agent-teaching on bad input: `mcp-tool-input-teaching.ts` maps each tool to a `teaching*` function that inspects a `ZodError` (path analysis, top-level field checks, URI shape heuristics) and returns a structured payload with `error: 'INVALID_TOOL_INPUT'`, `next_action`, `invalid_fields`, and an `example`. A per-scope in-memory retry counter (`retryCounters`) keyed by execution id / idempotency key / session / IP caps retries at 3 over 60s, injecting `must_obey` and `next_action` guidance. `buildMcpInputTeachingPayload` dispatches by tool name; `mcpToolInputValidationErrorResult` wraps it as an MCP error result.
- Shared helpers: `mcp-loose-input-schema.ts` exposes `mcpLooseToolInput(strict)` — a Zod union of the strict schema plus `z.record(z.string(), z.unknown()) | undefined | null` so the MCP SDK never rejects malformed JSON before the handler can emit teaching feedback. `local-artifact-dir-contract.ts` defines the `squadrules_local_artifact_dir` JSON field contract used to hand off client-side filesystem paths to shell challenges. `mcp-runtime-error.ts` translates `EmbeddingRateLimitError` into a structured `EMBEDDING_RATE_LIMIT` MCP error result, returning `null` for non-rate-limit errors so callers preserve existing rethrow behavior.
Dependency direction: this module imports schemas from sibling `*_schema.js` files and UI constants from `../mcp-apps/squadrules-ui-constants.js`, but is itself imported by server/route layers — no reverse dependencies.
