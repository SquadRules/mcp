Two sibling tool entry points share a common shape: `registerTrainTool` in `src/tools/train.ts` and `registerTuneTool` in `src/tools/tune.ts` both call `server.registerTool`, wrap input through `mcpLooseToolInput` + Zod schemas (`train_schema.ts`, `tune_schema.ts`), emit OpenTelemetry metrics via `../services/metrics/mcp-metrics.js`, and delegate business logic to pure functions.

- Train path: `train.ts` → `executeTrain` → `executeTrainStore` (in `train-store.ts`, outside this scope) plus helpers for artifact MIME resolution, source-adapter forking via `dump.js`, and directory-based batch scanning. Errors are normalized through `formatTrainErrorPayload` into a stable error contract (`DUPLICATE_ADAPTER`, `SIMILAR_MEMORY_FOUND`, etc.).
- Tune path: `tune.ts` → `executeTune` in `tune-execute.ts`, which branches on operation kind — pure space reassignment, in-place markdown tuning (`tuneAdapterMarkdownInPlace`), or delegated per-layer updates via `update.js`. Post-write persistence is verified by `tune-verify.ts` (re-read from Qdrant and compare text). Successful writes trigger `invalidateTuneCache` (`tune-cache-invalidation.ts`) to evict Redis caches so subsequent reads see fresh data.
- Shared utilities: `tune-messages.ts` normalizes result messages and rewrites layer URIs; `squadrules-uri.ts` provides the canonical `squadrules://adapter/{slug}` / `squadrules://layer/{uuid}` URI format used across both tools.

Dependency direction is one-way outward: these files depend on `services/qdrant/service`, `services/memory/*`, `services/redis-cache`, `utils/tenant-context`, and `utils/directory-access`, but nothing inside `services/` imports back into these tools.
