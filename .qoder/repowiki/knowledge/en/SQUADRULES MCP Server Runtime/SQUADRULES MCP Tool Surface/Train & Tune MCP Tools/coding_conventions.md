- Each MCP tool exposes a `registerXxxTool(server, memoryStore, options)` function that calls `server.registerTool` with `title`, `description` (resolved via `resolveToolDoc`), `inputSchema` wrapped by `mcpLooseToolInput`, and a typed `outputSchema`.
- Tool handlers follow a fixed lifecycle: capture `tenantId`, start `mcpToolDuration` timer, observe `mcpToolInputSize`, parse input with Zod `.safeParse`, return `mcpToolInputValidationErrorResult` on failure, then increment `mcpToolCalls`/`mcpToolErrors` and close the timer on success/error before returning `{ content, structuredContent }`.
- Cross-cutting state like target `space` is resolved through `resolveSpaceParamForContext` against the tenant context, with `'personal'` treated as a special literal and errors mapped to stable codes (`SPACE_NOT_FOUND`, `SPACE_READ_ONLY`).
- Write paths that modify adapter markdown require critic-loop approval: `review_evidence` (verdict_file, exit_code, stdout) is validated via `assertReviewEvidencePassed` in both train and tune flows, enforced at the Zod `superRefine` level and again in the executor.
- URIs are handled exclusively through the `squadrules://` scheme helpers (`parseSquadrulesUri`, `buildLayerUri`, `assertWireAdapterUri`) rather than ad-hoc string parsing, ensuring canonical layer/adapter identifiers throughout.
- Post-write durability is guarded by re-reading persisted data and comparing it to expected values (see `verifyTuneLayerPersistence`), catching silent no-op writes from stale caches.
