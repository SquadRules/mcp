Single MCP tool entry point (`export.ts`) dispatches on `format` to specialized sub-handlers while sharing a common Zod schema layer:
- Schema contract: `export_schema.ts` defines `ExportInput` / `ExportOutput` via Zod enums for formats (`markdown`, `source`, `skill_tree`, `skill_zip`, `trace_jsonl`, `reward_jsonl`, `sft_jsonl`, `preference_jsonl`) and cross-field validation (exactly-one selection mode, single-uri constraints for training/source formats, max 256 adapters, `delivery` only with `skill_zip`).
- Selection resolution: `export-selection.ts` normalizes adapter URIs (slug → `squadrules://adapter/{slug}`), deduplicates slugs, and expands `all_adapters` by enumerating space-scoped adapters.
- Adapter resolution: `export-resolve-adapter.ts` resolves a URI to `{adapterId, layerId}`, using Qdrant slug lookup when available and falling back to in-memory store lookups.
- Format handlers: `export-source.ts` handles `source` (artifact list or single artifact content); `export-reward-jsonl.ts` transforms execution traces into reward/SFT/preference NDJSON shapes; `export-skill-items.ts` + `skill-export/*` build skill trees and ZIP bundles (with optional base64 inline delivery or short-lived download capability).
- Directory bulk export writes per-adapter `<slug>.md` files with a manifest returned alongside the response.
- Telemetry wraps every call in `runExportExportTelemetryContext` / `finalizeExportObservation`; metrics are recorded via `mcp-metrics` around input/output size, duration, and error counts.
- Dependency direction is one-way: `export.ts` orchestrates and imports helpers; helpers never import back. External services (`MemoryQdrantStore`, `QdrantService`, `executionTraceStore`, `artifact-catalog`) are injected rather than imported directly.
