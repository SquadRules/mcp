- MCP tool registration follows a fixed pattern: expose a `registerXxxTool(server, deps)` function that calls `server.registerTool` with `title`, `description` resolved via `resolveToolDoc`, `inputSchema` wrapped in `mcpLooseToolInput`, and `_meta` UI constants.
- Every tool handler wraps execution in tenant-scoped metrics: record `mcpToolInputSize`, start a `mcpToolDuration` timer, increment `mcpToolCalls`/`mcpToolErrors` on both success and error paths, and return structured error results via `mcpToolInputValidationErrorResult` / `mcpRateLimitErrorResult`.
- Schemas are defined as exported Zod objects whose inferred TypeScript types (`z.infer<typeof schema>`) are re-exported as named types (e.g. `ActivateInput`, `ActivateOutput`) for consumers.
- Choice payloads are modeled as a discriminated union on a `role` field (`match` | `refine` | `create`) with role-specific extensions of a common base schema, keeping shared fields in `activateChoiceCommonSchema`.
- Artifact loading isolates failure from absence: `loadLinkedArtifacts` catches errors and returns `{ linkedArtifacts: [], artifactLoadError }` rather than throwing, so callers can emit a warning instead of silently claiming no artifacts exist.
