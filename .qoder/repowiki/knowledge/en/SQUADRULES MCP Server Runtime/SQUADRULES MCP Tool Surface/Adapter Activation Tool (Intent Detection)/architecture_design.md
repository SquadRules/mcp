Three-file leaf under src/tools/ implementing one MCP tool:
- `activate_schema.ts` declares the Zod schemas for input (`ActivateInput`) and output (`ActivateOutput`), including a discriminated union over three choice roles (`match`, `refine`, `create`) and nested schemas for `forward_first_call`, `linked_artifacts`, and `materialize` instructions.
- `activate-artifacts.ts` is a pure helper: resolves an adapter URI to its artifacts via `listAdapterArtifacts`, mint per-artifact download capabilities, and build `MaterializeInstruction` objects; it distinguishes a failed lookup from "no artifacts" by returning `{ linkedArtifacts: [], artifactLoadError }` so callers can warn agents not to run unknown script paths.
- `activate.ts` wires everything together: `registerActivateTool` registers the MCP tool, validates input through `mcpLooseToolInput(activateInputSchema)`, emits metrics (`mcpToolCalls`, `mcpToolDuration`, `mcpToolErrors`, `mcpToolInputSize`, `mcpToolOutputSize`), and delegates business logic to `executeActivate`. The execute path branches on `input.authoring` (routes to the built-in Author Adapter via `resolveExportAdapter`) versus normal search flow (`executeSearch` → `mapSearchToActivate`). Refinement sequences are tracked via `activateRefinementStore.incrementRefineCount` keyed by `execution_id`, capping refine-footers at two iterations. Transport-awareness (`stdio` vs `http`) drives whether artifact URIs use `squadrules://artifact/{slug}` + `squadrules export` or HTTP download URLs.

Dependency direction is inward-only: this module depends on `services/memory/store`, `services/qdrant/service`, `services/export-*`, `services/metrics`, `utils/*`, and sibling tools (`search`, `export-resolve-adapter`, `local-artifact-dir-contract`, `artifact-catalog`, `artifact-materialize-command`, `artifact-relative-path`).
