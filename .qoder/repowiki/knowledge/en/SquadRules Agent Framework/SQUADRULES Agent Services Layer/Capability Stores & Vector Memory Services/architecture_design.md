The module is organized as a set of capability services, each exposing a backend-selected singleton that swaps between Qdrant (networked) and LanceDB (embedded) implementations:

- `vector-store/` defines the backend-neutral ports (`IVectorRecordStore`, `IExecutionTraceStore`) and domain types in `types.ts`; `lancedb/` implements them via Arrow/Lance. `execution-trace-store.ts` and `qdrant/service.ts` both export a module-level singleton selected by `isQdrantConfigured`, so callers never import a Qdrant client on the embedded path.
- `qdrant/` is the Qdrant-specific implementation split into focused files: `connection.ts` (reconnect wrapper), `initialization.ts`, `memory-store.ts`, `memory-retrieval.ts`, `memory-updates.ts`, `search.ts`, `protocol.ts`, `listing.ts`, `quality.ts`, `resources.ts`, `reward-propagation.ts`, `snapshots.ts`. `service.ts` re-exports these modules behind a single `QdrantService` facade.
- `embedding/` provides provider abstraction over OpenAI / TEI / fastembed via `provider-resolver.ts` + `providers.ts`, with `audit.ts`, `health.ts`, `lazy-probe.ts`, and `bm25-tokenizer.ts` as cross-cutting concerns; `service.ts` exposes `EmbeddingService` and `probeEmbeddingDimension()`.
- `memory/` builds the high-level adapter/memory protocol on top of the vector store: `store.ts` orchestrates `adapter-builder.ts`, `store-methods.ts`, `store-title-similarity-search.ts`, `activation-*` helpers, and `validate-*` protocol validators.
- `key-value-store-factory.ts` selects `RedisService` vs `MemoryStore` (in-memory Map-based KV with TTL, hashes, counters, glob-key matching) based on `isRedisConfigured`; `redis-cache.ts` wraps it for search/memory cache invalidation via pub/sub.
- `metrics/` centralizes Prometheus instrumentation via `@prometheus-io/client` registry (`registry.ts` sets default labels `service`, `squadrules_version`, `instance`); per-subsystem files (`agent-metrics`, `anomaly-metrics`, `embedding-metrics`, `http-metrics`, `mcp-metrics`, `memory-metrics`, `qdrant-metrics`, `system-metrics`, `export-metrics`) register their own metrics.
- Top-level files (`oidc-state-store.ts`, `proof-of-work-store.ts`, `reward-evals.ts`, `reward-metrics.ts`, `forward-runtime-store.ts`, `id-generator.ts`, `stats/`, `export-*-capability*.ts`) provide supporting capabilities consumed by HTTP tools.

Dependency direction: higher layers (`memory/`, `qdrant/service.ts`, `embedding/service.ts`) depend on lower abstractions (`vector-store/types.ts`, `key-value-store.ts`, `metrics/registry.ts`); backends (`qdrant/*`, `vector-store/lancedb/*`) do not import each other.
