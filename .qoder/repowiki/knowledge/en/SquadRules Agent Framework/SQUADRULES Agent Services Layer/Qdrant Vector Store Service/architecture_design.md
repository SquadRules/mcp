Layered service module with a single public facade `QdrantService` (service.ts) that delegates to domain-scoped modules: connection.ts owns the `@qdrant/js-client-rest` client plus resilient retry/reconnect via exponential backoff; initialization.ts handles collection/alias lifecycle; memory-store.ts / memory-retrieval.ts / memory-updates.ts implement upsert, scroll, and patch operations on memory points; search.ts wraps vector similarity search; listing.ts provides category/domain overviews; protocol.ts resolves protocol step records; quality.ts tracks retrieval/success metrics; reward-propagation.ts propagates completion-layer rewards to adapter heads; resources.ts handles multi-item resource upserts; snapshots.ts streams Qdrant snapshot files via HTTP fetch + Node streams; utils.ts centralizes payload sanitization, UUID validation, and env parsing. Dependency direction is strictly inward: all feature modules depend only on `connection.ts`, never on each other, and the facade re-exports them. A runtime double-cast singleton (`qdrantService`) swaps in an embedded LanceDB store when Qdrant is not configured, so callers import from this package without branching. The `undici-compat.ts` shim patches `globalThis.fetch` to strip the incompatible `dispatcher` field injected by qdrant's vendored undici v6 on Node 25+.
