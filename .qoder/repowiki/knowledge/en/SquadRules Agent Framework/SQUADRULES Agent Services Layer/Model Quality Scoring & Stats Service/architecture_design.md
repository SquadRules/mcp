Single orchestrator class `ModelStatsService` (model-stats.ts) exposes the public API while delegating pure computation to four sibling modules: `scoring.ts` (specificity/expertValue/broadUtility/longevity → QualityScore), `bonuses.ts` (Wilson-adjusted implementation bonus with rarity/comparative multipliers), `healer.ts` (experience-multiplied healer improvement bonus), and `protocol.ts` (workflow-level potential aggregation over Qdrant protocol steps). Types live in `types.ts`. State (`recentDiscoveries`, per-model `implementationBonuses`, `healerBonuses`) is persisted through `keyValueStore` under keys `stats:state`, `stats:implementationBonusTotals`, `stats:rareSuccessCounts`; on init the service lazily connects Redis and falls back to in-memory defaults. Cross-cutting metrics are emitted via `agent-metrics` (OpenTelemetry-style counters/observers) scoped by tenant via `getTenantId()`. Protocol quality queries Qdrant via dynamic `import('../qdrant/index.js')` to avoid circular dependencies at module load time.
