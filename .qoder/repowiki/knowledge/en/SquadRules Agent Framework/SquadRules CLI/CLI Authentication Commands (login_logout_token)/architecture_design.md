Three sibling command modules registered with Commander.js, sharing a common auth runtime centered on `login.ts`:
- `login.ts` is the authority: it exposes `getBaseUrl()`, `isLocalAuthTarget()`, `writeLocalAuthFallbackHint()`, `isTokenValid()`, and `loginWithBrowser()` which are re-exported by `logout.ts` and `token.ts`. It also defines the `LoginWithBrowserOptions` interface used across the module.
- `logout.ts` is a thin wrapper that calls `writeConfig({ apiUrl, bearerToken: null })` against the resolved base URL.
- `token.ts` reads config, optionally triggers `loginWithBrowser` (`--login`) and validates via `isTokenValid` (`--validate`), then prints the raw token to stdout for scripting.
- Auth flows use Node's built-in `http.createServer` to host an ephemeral localhost callback server for the OAuth PKCE redirect; the port can be pinned via `SQUADRULES_LOGIN_CALLBACK_PORT` for tests. Token exchange uses `authorization_code` grant with `code_challenge_method=S256` against the server's `.well-known/oauth-protected-resource` metadata.
- Local-target handling: when the resolved target is the local sentinel, commands fall back to `http://localhost:3000` and emit a hint, since the local transport has no auth server.
- Dependencies point outward to `../config-file.js` (read/write persisted config), `../keyring.js` (optional keychain storage), `../oauth-refresh.js` (OAuth metadata + client id), `../output.js` (structured stdout/stderr), `../resolve-timeout.js` (shared timeout resolution), and `../auth-error.js` (browser opener). No inward dependencies from other modules except the exported helpers consumed by `logout`/`token`.
