The module centers on the `ActionBackend` interface in `action-backend.ts`, which declares the canonical command surface (`activate`, `forward`, `train`, `trainJson`, `tune`, `delete`, `reward`, `spaces`, `export`) plus an optional `downloadExportRef` capability. Two implementations sit behind it:
- `HttpBackend` (http-backend.ts) is a thin passthrough over `ApiClient`, forwarding every call to the remote server while preserving auth/refresh, timeout/retry, and endpoint semantics.
- `LocalBackend` (local-backend.ts) boots an embedded runtime via `bootLocalRuntime` with fastboot defaults, then delegates each method to the same `execute*` core functions used by HTTP routes and MCP tools, ensuring local and remote results are identical; embeddings load lazily only when needed (`ensureEmbeddingDimension`).

`resolve-backend.ts` is the entry point: `resolveBackendTarget` picks between local and http based on the resolved `--url` target (defaulting to the `stdio://local` sentinel), and `createBackendFromProgram` constructs the concrete backend, dynamically importing `LocalBackend` so http-only invocations never load the embedding stack. Dependency direction is one-way: both backends depend on `action-backend.ts`; `resolve-backend.ts` depends on both backends; nothing inside this directory imports from higher layers except shared types from `src/tools/*_schema.js` and `../upload-guards.js`.
