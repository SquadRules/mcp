Each file registers one Commander command by calling `program.command(...)` inside an exported `*Command(program)` function that the parent CLI wires up. All commands share a uniform shape: parse options → resolve backend via `createBackendFromProgram(program)` → call a method on `ActionBackend` (`export`, `train`, `tune`, `delete`) → render through `emitResult(resolveOutputFormat(program), response, { pretty, text })` with pretty/text renderers from `../render.js`. Error handling is centralized in `handleApiError(error, !isBrowserDisabled())` imported from `../auth-error.js`. Cross-cutting concerns are factored out: shared descriptions live in `delete-metadata.ts`; markdown upload validation goes through `upload-guards.readMarkdownUploadFromFile`; directory-batch training is delegated to `../train-batch.runTrainBatch`; skill-zip artifact writing is delegated to `../skill-zip-local-write.resolveSkillZipOutputPath`. The export command additionally exposes pure helpers (`buildExportInput`, `writeExport`, `assertDirectorySupportedByBackend`) so its selection/validation logic can be reused outside the CLI action. Dependency direction is strictly inward toward `../backend/*`, `../output.js`, `../format.js`, `../render.js`, and `../auth-error.js` — no cross-imports between sibling command files except the shared metadata constants.
