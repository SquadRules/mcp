Single entrypoint `src/tools/export.ts` registers the `export` MCP tool and dispatches on `input.format` to one of several export paths: flat markdown, directory dump, trace/reward/sft/preference JSONL, `skill_tree`, or `skill_zip`. Adapter resolution goes through `resolveExportAdapter` + `resolveExportUris`; protocol content is fetched via `executeDump` from `squadrules://layer/...`. The `skill-export/` sub-package implements the skill-bundle pipeline: `assemble-skill-item.ts` builds a `SkillExportItem` from adapter markdown, `build-skill-md.ts` renders the final `SKILL.md`, `derive-metadata.ts` extracts slug/name/description, `scan-diagnostics.ts` produces diagnostics, `sha256.ts`/`sha256sums.ts` compute digests, and `zip-bundle.ts` streams archives via `archiver` (`pipeSkillZipToWritable` for HTTP responses, `zipSkillFiles` for in-memory base64). The nested `artifact-sanitization/` sub-package exposes a rule-based pipeline (`runArtifactSanitization`) with pluggable `ArtifactSanitizationRule`s; default rules live in `default-rules.ts` and an extension-mime consistency rule lives under `rules/`. Output is wrapped by `export-telemetry.ts` for duration/error metrics and `export-download-capability.ts` minting temporary download refs when `delivery !== 'inline_base64'`. Dependency direction is strictly inward: `export.ts` depends on `skill-export/*`, which depend only on shared services (`memoryStore`, `qdrantService`, `executionTraceStore`) — no sibling tools are imported from within `skill-export/`.
