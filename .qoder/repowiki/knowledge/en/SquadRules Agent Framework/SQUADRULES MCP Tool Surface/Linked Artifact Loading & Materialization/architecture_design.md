Three cooperating files form a thin pipeline between Qdrant-backed artifact storage and the agent workflow:
- `artifact-catalog.ts` is the read layer: it queries `MemoryQdrantStore.listAdapterArtifacts`, coerces raw Qdrant payloads into the typed `AdapterArtifactMetadata` schema (with fallbacks for missing fields), and returns a sorted list.
- `activate-artifacts.ts` is the orchestration entry point used by the activate flow: it resolves the adapter URI to an adapter id via `resolveExportAdapter`, fetches metadata from the catalog, generates per-artifact download capabilities through `mintExportArtifactDownloadCapability`, and produces `LinkedArtifactRow` objects whose `download_url` switches between an HTTP capability URL and a `squadrules://artifact/...` stdio URI depending on transport.
- `artifact-materialize-command.ts` emits a `MaterializeInstruction` — a declarative MCP call contract (`tool: 'export'`, `format: 'source'`) plus `out`, `sha256`, and `chmod: '700'` — so any MCP-connected agent can materialize scripts without a CLI dependency; the output path is templated against the `SQUADRULES_LOCAL_ARTIFACT_DIR` environment variable.
Dependency direction is one-way: activate → catalog + materialize-command + export-capability; no file in this module imports from the others except activate importing both siblings.
