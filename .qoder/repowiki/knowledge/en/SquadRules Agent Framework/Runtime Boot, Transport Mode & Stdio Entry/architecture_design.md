Four thin sub-packages with a clear dependency direction:
- `src/config/` holds pure env-resolution helpers split out of the monolithic `config.ts` to respect its max-lines budget: `runtime-mode.ts` derives `TRANSPORT_TYPE`, `AUTH_ENABLED`, and `isQdrantConfigured` from `process.env` (with explicit `TRANSPORT_TYPE`, `SQUADRULES_MCP_STDIO`, `SQUADRULES_CLI_SERVE` keys) and validates that `stdio` + auth or external Qdrant is rejected via `getStdioConfigViolations`; `mem-boot.ts` exposes the `MEM_BOOT_FORCE_INJECT` repair hatch; other files (`embedding-fastembed.ts`, `export-*`, `adapter-markdown-size-limits.ts`) are small env/value shims.
- `src/runtime/boot-local-runtime.ts` is the shared startup orchestrator factored out of `runSquadrulesServer()` so both the HTTP server and the CLI local backend execute the same sequence: select LanceDB vs Qdrant store, optionally probe embedding dimension, wait for Qdrant health, init the store, trigger a snapshot, then seed app-space adapters according to a `SeedMode` (`always` / `auto` / `never`).
- `src/stdio/` is the stdio transport entry: `stdio-server.ts` wires `@modelcontextprotocol/sdk/server/stdio.js`'s `StdioServerTransport` into `createServer(memoryStore)`; `stdio-banner.ts` composes a stderr-only banner (stdout carries JSON-RPC frames) showing store, embedding provider, auth posture, and the fact that HTTP endpoints are unavailable in simple mode.
- `src/constants/builtin-search-meta.ts` defines the built-in protocol slugs (`refine-search`, `author-adapter`) and derives their footer labels from embedded meta docs rather than hardcoding strings.

Dependency direction is one-way: `stdio` → `runtime` → `config` → services; nothing in `config` imports runtime code. The module deliberately keeps side effects at the edges (banner printing, boot orchestration) and leaves env resolution as pure functions over an env record for unit-testability.
