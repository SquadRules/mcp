Two sibling sub-folders with no internal dependencies between them:
- `src/ui/lib/` holds higher-level, cross-cutting concerns. `api.ts` is the single HTTP entry point (`apiFetch`) that normalizes base URL resolution, JSON content-type, and same-origin credentials; `export-skill-zip.ts` builds on it to call `/api/export`, resolve either a server-provided `download_ref.url` or inline base64 into a Blob, and drive browser file downloads via `triggerFileDownload`. `runToolTypes.ts` re-exports and narrows types from `../../tools/forward_schema.js` so UI components import `RunContract`, `RunLayer`, etc. without coupling directly to the tools package.
- `src/ui/utils/` contains pure, framework-agnostic helpers: `browse-adapters.ts` flattens nested space→adapter trees, dedupes by `adapter_id` preferring higher `layer_count`, and computes per-letter counts against a fixed `BROWSE_LETTERS` alphabet; `confidence.ts` clamps/scales a score to a 0–100 integer; `rich-text-editor-extensions.ts` centralizes TipTap extension setup (StarterKit, Link, Table, Markdown) consumed by protocol step editors.
Dependency direction is one-way: lib → apiFetch; utils have no runtime imports beyond their own scope and shared type packages.
