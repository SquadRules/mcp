The `http-server.ts` entry point is the sole wiring point: it creates one Express app, applies shared middleware (helmet, rate limiting, logging, metrics via `http-server-config.js`), registers the OIDC callback (`http-auth-callback.ts`) before any route, then installs `/api/.well-known/openid-configuration` and CORS preflight routes *before* the bearer/OIDC auth middleware so unauthenticated clients can discover capabilities. After `authMiddleware`, routes are mounted in capability order: health → export downloads → export artifact downloads → REST API (`http-api-routes.ts`) → MCP transport (`http-mcp-handler.ts`) → UI static files → error handlers. Cross-child contracts are: (1) all route modules receive `memoryStore` (and where needed `qdrantService`) as constructor-like arguments rather than importing services directly; (2) authentication is centralized in `http-auth-middleware.ts` which attaches the authenticated user to the Express request for downstream handlers; (3) structured audit events flow from MCP handlers through `mcp-audit-emit.ts` into the shared logger. The child modules are therefore isolated by route path and by the explicit dependency injection of `MemoryQdrantStore`/`QdrantService` at registration time.
