Three cooperating files form the MCP HTTP entry point:
- `http-mcp-handler.ts` registers `POST /mcp`, creates a per-request `StreamableHTTPServerTransport` + MCP server via `createServer`, resolves Bearer tokens through `validateBearerToken`, runs handlers inside an `AsyncLocalStorage` (`mcpRequestStore`) scoped to space/tenant context, and applies a process-wide concurrent request counter (503 when exceeding `MAX_CONCURRENT_MCP_REQUESTS_RAW`). It also special-cases `listOfferingsForUI` so unauthenticated clients receive a proper JSON-RPC auth error instead of `-32601 Method not found`.
- `mcp-audit-emit.ts` is isolated from the handler to satisfy the max-lines lint rule; it wraps `transport.send` to capture JSON-RPC responses at level 3, generates correlation IDs, and writes `audit.mcp` events (`mcp_request_start`, `mcp_request_end`, `mcp_tool_call`) via `writeAuditLine`, with request/response bodies summarized by `audit-mcp-summary.js` only at levels 2/3.
- `mcp-ui-offerings-auth-jsonrpc.ts` provides the implementation-defined JSON-RPC error code `-32001` and helper builders for the `listOfferingsForUI` auth-required response, including an OIDC login URL via `safeCreateOidcLoginUrlForApiResponse`.

Dependency direction is one-way: handler → audit emit → structured logger/config; UI offerings helpers depend only on the OIDC redirect helper. The module depends outward on `../server.js`, `../services/memory/store.js`, `../utils/concurrency-limit.js`, `../utils/tenant-context.js`, `../mcp-apps/list-offerings-for-ui.js`, and `./bearer-validate.js` / `./http-auth-middleware.js`.
