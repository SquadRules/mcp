Three-file bootstrap layer for the Express application:
- `http-server.ts` is the composition root: it constructs the Express app, registers modular route/middleware setup functions (`configureMiddleware`, `setupAuthCallback`, `setupWellKnown`, `setupMcpCorsRoutes`, `authMiddleware`, `setupHealthRoutes`, `setupApiRoutes`, `setupMcpRoutes`, `setupUiStatic`, `setupExportDownloadRoutes`, `setupExportArtifactDownloadRoutes`, `setupErrorHandlers`) in a strict order that places `/well-known` and CORS before auth so MCP discovery works unauthenticated, then delegates lifecycle to `startHttpServerWithErrorHandling`. It also exposes `startHttpTransport` as the entry point used by the rest of the process.
- `http-server-config.ts` centralizes cross-cutting Express middleware: structured HTTP access logging, Prometheus metrics, helmet CSP (minimal, API-only), per-route-group rate limiters via `express-rate-limit` on `/auth`, `/api`, `/mcp`, and JSON body parsing with a configured size cap. Rate limits are parameterized through constants from `../config.js`.
- `http-server-startup.ts` wraps `app.listen` with an `EADDRINUSE` handler that logs and exits the process, returning the Node `http.Server` instance.

Dependency direction is one-way outward: this module imports services (`MemoryQdrantStore`, `qdrantService`), config, and utilities but is not imported by them; it only exports the two start functions consumed by higher-level bootstrappers.
