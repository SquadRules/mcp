- `http-api-routes.ts` is the single composition root: `setupApiRoutes(app, memoryStore, deps)` imports each per-endpoint module and calls its `setupXxxRoute(app, ...)` factory in a fixed order, passing shared dependencies (`MemoryQdrantStore`, `QdrantService`) so route handlers stay thin.
- Each endpoint lives in its own file under `src/http/` (e.g. `http-api-begin.ts` → `/api/activate`, `http-api-me.ts` → `/api/me`), exposing only a `setupXxxRoute` factory — this keeps route registration declarative and testable.
- Business logic is delegated to `../tools/*` (e.g. `executeActivate` from `../tools/activate.js`) and `../services/*`, so this layer owns only HTTP concerns: request parsing, validation, error mapping, and response serialization.
- Input validation uses Zod schemas imported from `../tools/*_schema.js` (e.g. `activateInputSchema.safeParse`); failures return a uniform `{ error: 'INVALID_INPUT', message }` shape.
- Cross-cutting concerns are centralized: `runHttpApiWithSpaceContext` wraps handler execution for tenant/space scoping, `structuredLogger` logs requests, and `sendToolRouteError` normalizes tool exceptions into `{ error, message }` responses via `http-route-errors.js`.
- Authenticated routes like `/api/me` rely on an earlier middleware that attaches `req.auth: AuthPayload`; the handler derives `account_kind`/`account_label` from OIDC claims via `oidc-profile-claims.js` and whitelists fields into `MeResponse`.
