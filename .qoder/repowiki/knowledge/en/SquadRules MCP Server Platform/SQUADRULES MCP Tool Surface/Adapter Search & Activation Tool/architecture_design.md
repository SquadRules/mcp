Three-file leaf module split by concern:
- `search_schema.ts` declares Zod schemas (`searchInputSchema`, `searchOutputSchema`) plus the `SearchInput`/`SearchOutput` types used as the MCP tool contract; input is validated against min/max limits from `../config.js`.
- `search_output.ts` is pure output assembly: `createResults` normalizes scores (sigmoid pivot 0.5), resolves head URIs via `resolveAdapterEntry`, builds `UnifiedChoice[]` with match/refine/create roles, deduplicates collapsed chain roots, and appends built-in refine/create footer choices.
- `search.ts` is the runtime entry: `executeSearch` is the exported function used by both the MCP tool and HTTP route. It sanitizes built-in protocol slugs out of queries, runs a two-phase Qdrant search (`searchAndBuildCandidates` with group-collapse then fallback without collapse), merges candidates via `addCandidate` (preferring layer_index=1 heads, personal-space tiebreak), applies `SCORE_THRESHOLD`, logs anomalies, and wraps execution in an activate:v6 cache keyed by space/query/groupCollapse/limit with a 300s TTL through `redisCacheService`. An optional `runInSpace` option lets callers re-run inside a different space context.
Dependency direction is inward only: this module depends on `services/qdrant`, `services/memory`, `services/embedding/audit`, `utils/tenant-context`, `utils/space-display`, and `constants/builtin-search-meta`; it does not depend on any other `src/tools/*` except `squadrules-uri.ts` for URI construction.
