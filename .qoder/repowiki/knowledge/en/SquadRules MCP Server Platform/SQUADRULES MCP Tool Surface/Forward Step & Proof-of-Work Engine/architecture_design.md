The module centers on `next.ts`, which exposes `_executeNext` (used by both the MCP forward bridge and legacy HTTP route) as the single entry point for advancing an adapter layer. It composes several focused helpers:

- Schema contract: `next_schema.ts` defines Zod schemas (`nextInputSchema`, `nextOutputSchema`, `solutionSchema`, `challengeSchema`) that form the public API between the server and agents; `next-proof-types.ts` mirrors these as TS types (`ProofOfWorkSubmission`, `HandleProofResult`, etc.).
- Challenge construction: `next-pow-challenge-shape.ts` renders a challenge shape from a `ProofOfWorkDefinition` without touching stores; `next-pow-helpers.ts` adds nonce rotation, TTL refresh via `proofOfWorkStore`, and dispatches type-specific validation in `handleProofSubmission` (shell exit code, MCP contract match via `mcp-contract-match`, user_input elicitation through MCP client capabilities, comment semantic similarity via `embeddingService`).
- Previous-step recovery: `next-previous-step.ts` provides `tryApplySolutionToPreviousStep` and `tryApplySolutionToPreviousStepWhenSolutionMatchesPrevious`, letting the engine accept a solution intended for the prior layer when the current layer lacks a stored inference contract — this is what turns a `MISSING_PROOF` block into a recoverable flow.
- Missing-proof response builder: `next-missing-proof-payload.ts` constructs the `current_step` + `challenge` for the previous layer so the agent can re-attempt it with the correct nonce and `proof_hash`.
- Shell invocation helpers: `shell-challenge-invocation.ts` builds logical argv for shell challenges (bash `-c`, python/perl/node `-e`, terraform/docker 'other' style) and formats display strings; used to populate `invocation_display` in challenges.

Dependency direction is one-way: `next.ts` → helpers → services (`adapter-navigation`, `memory-accessors`, `proof-of-work-store`, `qdrant-service`, `redis-cache`, `embedding-service`, `model-stats`). The module never imports sibling tools directly except for shared utilities like `squadrules-uri`, `local-artifact-dir-contract`, and `squadrules-genesis-proof-hash`. Quality metrics are updated via `updateStepQuality`, which writes Qdrant quality metadata and emits `squadrulesQualityUpdateErrors` on failure.
