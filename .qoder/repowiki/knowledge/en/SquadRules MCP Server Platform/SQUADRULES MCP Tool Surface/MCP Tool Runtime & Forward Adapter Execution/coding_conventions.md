- MCP tool handlers wrap body execution in try/catch that increments `mcpToolCalls.inc({status})` and `mcpToolErrors.inc()` on failure, then returns either a success `{content, structuredContent}` or an `{isError: true, content:[{type:'text', text}]}` result.
- Zod validation failures are converted to agent-friendly payloads via `mcpToolInputValidationErrorResult(tool, zodError, raw)`, which dispatches per-tool teaching functions producing `error`, `message`, `next_action`, `invalid_fields`, and `example` fields.
- Retry pressure is tracked with a process-wide `Map<string, {count, expiresAt}>` keyed by idempotency/session/IP, capping at `MAX_INPUT_RETRIES=3` with a 60s TTL, and surfaced as `retry_count` / `max_retries` / `must_obey` in teaching payloads.
- Structured MCP error responses use the uniform shape `{ isError: true, content: [{ type: 'text', text: JSON.stringify(payload) }] }` rather than throwing, so clients can parse actionable JSON instead of raw strings.
- Adapter URIs are normalized through `parseSquadrulesUri` and resolved to `{adapterId, layerId}` pairs, with slug lookups gated behind an optional `QdrantService` fallback to `MemoryQdrantStore`.
