Two cooperating sub-areas live side-by-side:

- Forward execution layer: `forward-register.ts` is the entry point — it calls `server.registerTool('forward', ...)` with schemas from `./forward_schema.js`, wraps `executeForward` (from `./forward.js`) in Zod validation (`forwardInputSchema.safeParse`), tenant-scoped metrics (`mcpToolCalls`, `mcpToolDuration`, `mcpToolErrors`, `mcpToolInputSize/OutputSize`), and structured error handling. `forward-helpers.ts` provides evidence templates per contract type; `export-resolve-adapter.ts` resolves a squadrules:// URI to `{adapterId, layerId}` using `MemoryQdrantStore` and optional `QdrantService` slug lookup.
- MCP runtime utilities: `mcp-tool-input-teaching.ts` maps each tool name (`activate|forward|reward|train|tune|delete|export|spaces`) to a human-readable retry payload via `buildMcpInputTeachingPayload`, including per-tool guidance and a process-wide retry counter keyed by idempotency/session/IP. `mcp-contract-match.ts` implements subset-based argument matching between a `ProofOfWorkDefinition.mcp` contract and an agent's submission. `mcp-runtime-error.ts` converts embedding provider rate-limit errors into structured MCP error results. `forward-tool-error.ts` and `forward-trace.ts` shape forward-specific errors and traces consumed by the register wrapper.

Dependency direction is one-way: this module depends on `../services/*`, `../types/*`, `../utils/*`, and `../mcp-apps/*`; nothing inside the module imports sibling tools beyond `forward.js` and `forward_schema.js`. The only public registration boundary is `registerForwardTool`.
