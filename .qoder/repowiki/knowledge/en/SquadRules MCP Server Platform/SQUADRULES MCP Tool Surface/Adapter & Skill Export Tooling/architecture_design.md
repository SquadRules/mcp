Single MCP tool entry point `export.ts` (`registerExportTool` + `executeExport`) dispatches on `input.format` to one of five output paths: flat `markdown`, `source` (delegated to `export-source.ts`), four JSONL training formats (`trace_jsonl`, `reward_jsonl`, `sft_jsonl`, `preference_jsonl` via `export-reward-jsonl.ts`), and the two skill-bundle formats (`skill_tree`, `skill_zip`). Input validation and cross-field constraints live in `export_schema.ts` (Zod schemas with `superRefine` enforcing exactly-one selection mode, single-URI restrictions for training/source formats, max 256 adapters, and `delivery` only for `skill_zip`). Selection resolution is isolated in `export-selection.ts` (`resolveExportUris`, `normalizeAdapterUri`, `dedupeSlug`, `rehomeItemFiles`). Skill bundle assembly is layered under `skill-export/`: `assemble-skill-item.ts` builds a `SkillExportItem` per adapter, `artifact-files.ts` loads attached artifacts, `sha256sums.ts` appends checksums, `build-skill-md.ts` renders SKILL.md, `enumerate-space-adapters.ts` lists all adapters in a space, `scan-diagnostics.ts` collects diagnostics, and `zip-bundle.ts` streams ZIP bytes via `archiver`. The nested `artifact-sanitization/` sub-package enforces artifact rules (extension/MIME consistency, default rules) before files enter the bundle. Telemetry uses Node `AsyncLocalStorage` (`export-telemetry.ts`) so concurrent exports keep per-request decoded-byte accounting isolated; metrics flow through `recordExportMetrics` and structured logging flags slow exports (>5s). Output delivery for `skill_zip` supports either inline base64 or an async `download_ref` minted by `services/export-download-capability.js`.
