Two parallel MCP tools share the same registration pattern: `train.ts` exposes `registerTrainTool` for creating adapters from markdown or artifacts (with optional fork-from-source), and `tune.ts` exposes `registerTuneTool` for updating existing adapter layers. Each file pairs a handler (`*.ts`) with a schema module (`*_schema.ts`) defining Zod input/output types. Handlers call into lower-level execution modules (`./train-store.js`, `./tune-execute.js`) and depend on shared utilities for tenant/space context resolution, squadrules URI parsing, artifact MIME inference, metrics emission, and error shaping. The train flow additionally resolves content from a source adapter via `executeDump`, enforces critic-loop review evidence through `assertReviewEvidencePassed`, and normalizes artifact-relative paths. Space scoping is resolved per-call via `resolveSpaceParamForContext` and injected as narrowed context around the store operation. Both tools emit OpenTelemetry-style metrics (`mcpToolCalls`, `mcpToolDuration`, `mcpToolErrors`, `mcpToolInputSize`, `mcpToolOutputSize`) and return structured MCP responses with both text and structuredContent payloads.
