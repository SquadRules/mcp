Each operation is split into two files: a `*_schema.ts` file declaring Zod input/output schemas (and exported TS types via `z.infer`), and a `*.ts` file exporting an `execute*` pure function plus a `register*Tool` MCP registration helper. The `execute*` functions take injected dependencies (`QdrantService`, `MemoryQdrantStore`) so they can be reused by the HTTP API layer as well as MCP. URI handling is centralized through `squadrules-uri.js` helpers (`parseSquadrulesUri`, `parseSquadrulesUriOrThrow`, `buildLayerUri`, `assertWireAdapterUri`). Metrics are recorded uniformly via `mcp-metrics.js` (`mcpToolCalls`, `mcpToolDuration`, `mcpToolErrors`, `mcpToolInputSize`, `mcpToolOutputSize`) around each tool invocation, with tenant context from `getTenantId()`. Input validation uses `mcpLooseToolInput` to wrap strict Zod schemas for agent-friendly loose parsing, and validation failures are normalized through `mcpToolInputValidationErrorResult`. `dump.ts` additionally supports protocol-mode aggregation across all layers of an adapter, caching memory reads through `redisCacheService`.
