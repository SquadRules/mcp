Three-file entry layer that wires the browser bundle to a React application:
- `index.html` is the HTML shell — it sets the document title, loads `/ui/favicon.svg`, injects an inline script that resolves the initial dark/light/system theme into `data-theme` on `<html>` before any JS runs, then mounts `<div id="root">` and imports `main.tsx` as an ES module.
- `main.tsx` is the React bootstrap: it creates a single `QueryClient`, renders under `StrictMode`, and composes providers in order — `QueryClientProvider` → `ThemeProvider` (from `./hooks/useThemePreference`) → `App`. It also imports `./i18n` for side-effect initialization and `./index.css` for global styles.
- `App.tsx` owns the route tree via `react-router-dom`'s `BrowserRouter` with `basename="/ui"` so the app can be served from a sub-path. Each page component (`HomePage`, `SquadrulesPage`, `RunsPage`, `ProtocolEditPage`, `RunGuidedPage`, `SkillBundlePage`, `ProtocolDetailPage`, `AccountPage`, `NotFoundPage`) is imported through `React.lazy` + dynamic `import()` and wrapped in `<Suspense fallback={<RouteFallback />}>` to keep the initial chunk under 500 kB. The `AppRoutes` function is exported separately so tests can mount it with `MemoryRouter`; the default export wraps it in `BrowserRouter` for production.
The dependency direction is strictly inward: this shell depends on sibling modules (`components/Layout`, `hooks/useThemePreference`, `pages/*`, `i18n`, `index.css`) but exposes no runtime API of its own beyond the root DOM node.
