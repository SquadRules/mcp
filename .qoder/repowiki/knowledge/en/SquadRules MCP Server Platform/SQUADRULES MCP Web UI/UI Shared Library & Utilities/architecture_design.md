Two sibling folders with no internal dependencies between them:
- `src/ui/lib/` — higher-level library code consumed by UI components. `api.ts` is the single HTTP entry point (`apiFetch`) that prefixes an empty `API_BASE`, forces JSON content-type, and uses `same-origin` credentials; it is the only place `fetch` is called directly. `export-skill-zip.ts` builds on top of `apiFetch` to POST `/api/export` (format `skill_zip`), then either follows a server-provided `download_ref.url` or decodes inline base64 into a Blob, plus helpers for triggering a browser download and deriving a filename from the skill bundle manifest. `runToolTypes.ts` re-exports and aliases types from `../../tools/forward_schema.js` (`ForwardOutput`, `ForwardSolution`) as `RunContract`/`RunLayer`/etc., keeping UI-facing names separate from tool-layer schema names.
- `src/ui/utils/` — pure, side-effect-free helpers. `browse-adapters.ts` flattens nested `SpaceInfo[]` into a deduplicated adapter list keyed by `adapter_id` (preferring higher `layer_count`), then computes per-letter counts using a fixed `BROWSE_LETTERS` alphabet. `confidence.ts` normalizes a nullable score into a 0–100 integer percentage. `rich-text-editor-extensions.ts` centralizes TipTap extension configuration (StarterKit, Link, Table, Markdown) used by protocol step body editors and their tests.

Dependency direction is one-way: utils have no cross-imports; lib depends on utils only via imports from other UI modules (e.g. `@/hooks/useSpaces`). Types flow inward from `src/tools/*_schema.js` through `lib/runToolTypes.ts` so UI code never imports tool schemas directly.
