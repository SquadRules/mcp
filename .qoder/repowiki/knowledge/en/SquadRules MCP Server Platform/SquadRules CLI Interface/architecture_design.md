Entry point `index.ts` boots the process, forcing log-sink setup before any shared logger is created, then auto-injects `serve` when stdin is piped (MCP host mode) and delegates to `createProgram().parseAsync`. `program.ts` registers every subcommand (`activate`, `forward`, `train`, `spaces`, `tune`, `delete`, `reward`, `export`, `serve`, `login`, `logout`, `token`) under the `squadrules` binary, propagating root flags (`--url`, `--timeout`, `--retries`, `--format`, `--no-browser`, `--reseed`) into `process.env` via a Commander `preAction` hook.

Backend abstraction lives in `backend/`: `resolve-backend.ts` picks between `HttpBackend` (remote REST via `ApiClient`) and `LocalBackend` (dynamic import of the embedded store, only loaded on local targets). Commands call `createBackendFromProgram(program)` rather than constructing transports directly, keeping the CLI flag → transport decision out of command handlers.

Configuration is layered: `config-file.ts` reads XDG-compliant JSON (`~/.config/squadrules/config.json`) supporting multi-environment keyed by normalized URL, migrating legacy flat shapes; secrets are preferentially read/written through `keyring.ts` (OS keyring) with `__KEYCHAIN__` placeholders in the file as fallback. `client-factory.ts` resolves `ApiClientOptions` (baseUrl, timeoutMs, maxRetries) from program globals + env vars + config defaults.

Output is split per-command into `render-helpers.ts` (color/ascii-table helpers), `render.ts` (pretty/text renderers for each domain output type), and `output.ts` (TTY-aware writer). Human-facing hints (e.g. `next:` shell snippet) go to stderr so they never corrupt JSON payloads on stdout.
