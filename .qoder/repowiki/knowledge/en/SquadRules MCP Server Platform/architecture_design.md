Two-process entrypoints converge on `src/index.ts` → `runSquadrulesServer()`: the direct Node entrypoint (`node dist/index.js`) and the pre-bootstrapped path via `src/bootstrap.ts` (which installs uncaughtException/unhandledRejection handlers before any app code loads). Both call `bootLocalRuntime()` from `src/runtime/boot-local-runtime.ts`, which is the single wiring point that initializes the memory store, embedding provider, Qdrant connection, LanceDB vector store, snapshot loading, and app-space seeding — then branches on `TRANSPORT_TYPE` to start either `startHttpTransport(memoryStore)` (Express REST + MCP JSON-RPC + OIDC + UI static assets) or `startStdioTransport(memoryStore)` (MCP-over-stdio). The `tools/` layer registers the canonical SQUADRULES tool surface consumed by both transports; `services/` provides the business logic behind those tools; `mcp_apps/` injects SEP-1865 widget resources into the same HTTP server; `resources/` serves embedded documentation and prompts as MCP resources; `ui/` is a React SPA served by the HTTP transport. The CLI (`src/cli/`) is a separate process that talks to the running server via HTTP or an embedded local target, reusing the same tool contracts rather than duplicating logic.
