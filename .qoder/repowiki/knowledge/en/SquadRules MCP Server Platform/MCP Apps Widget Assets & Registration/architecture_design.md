Each widget follows a fixed three-file layout: a `*-widget-html.ts` builder that concatenates an embedded SVG logo, a `*-widget-inline-css.ts` CSS string, and a `*-widget-inline-script.ts` self-contained IIFE, then passes the result through `minifyInlineWidgetHtml` and `substituteWidgetPresentationToken` to inject the presentation-only flag. A sibling `register-*-ui-resources.ts` calls `server.registerResource()` twice — once with `text/html;profile=mcp-app` on `ui://squadrules/*` and once with `text/html+skybridge` on `ui://open-ai/squadrules/*` — so both MCP Apps hosts (Cursor, Claude Desktop) and Skybridge hosts (ChatGPT, Windsurf) can render the same fragment. Shared cross-cutting concerns live in dedicated modules: `squadrules-ui-constants.ts` centralizes URIs, `_meta.ui.resourceUri` bindings, MIME types, and extension id; `mcp-widget-chrome-inline-css.ts` provides shared chrome tokens; `mcp-widget-presentation-inject.ts` swaps a sentinel token into scripts; `widget-inline-minify.ts` strips whitespace/comments from inline assets; `squadrules-server-ui-capability.ts` advertises the UI extension mimeTypes on initialize; `list-offerings-for-ui.ts` builds the combined tool/resource/prompt listing for host discovery. Dependency direction is one-way: widget builders depend on shared constants/minifiers, never the reverse; registration files depend only on builders and constants, keeping the server wiring (`src/server.ts`) free of widget internals.
