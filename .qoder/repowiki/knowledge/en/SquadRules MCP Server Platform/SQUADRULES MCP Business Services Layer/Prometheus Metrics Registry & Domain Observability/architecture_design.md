- `registry.ts` is the single source of truth: it creates a shared `prom-client` `Registry`, sets default labels (`service='squadrules'`, `squadrules_version` from build info, `instance` from env/hostname), and exposes it via the named export `register`.
- Every other file in this directory is a leaf module that imports `register` from `./registry.js` and declares one or more `Counter`/`Histogram`/`Gauge` instances with names prefixed `squadrules_`, passing `registers: [register]` so all metrics are collected by the same registry.
- Domain files are organized one-per-observability concern: `http-metrics.ts` (request counts/durations/sizes, active connections), `agent-metrics.ts` (contributions, bonuses, quality scores), `anomaly-metrics.ts` (heuristic anomaly events), `export-metrics.ts` (duration, request count, adapter count, ZIP size plus a `recordExportMetrics` helper), `embedding-metrics.ts`, `mcp-metrics.ts`, `memory-metrics.ts`, `qdrant-metrics.ts`, and `system-metrics.ts` (uptime, RSS/heap gauges updated every 5s via `setInterval`).
- Dependency direction is strictly inward: domain modules depend only on `registry.ts` and `prom-client`; nothing in this package imports business logic, keeping metrics side-effect free at import time except for the periodic updater in `system-metrics.ts`.
