Services are organized as feature sub-packages under `src/services/`, each exposing a facade singleton selected at import time by environment flags:

- Backend selection via config gates: `key-value-store-factory.ts` chooses `MemoryStore` vs `RedisService`; `execution-trace-store.ts` exports an `IExecutionTraceStore` resolved to `ExecutionTraceStore` (Qdrant) or `LanceExecutionTraceStore` (embedded); `qdrant/service.ts` exports `qdrantService` resolved to `QdrantService` or the shared `LanceVectorRecordStore` double-cast to the Qdrant shape.
- Shared embedded engine: `vector-store/embedded-store-singleton.ts` memoizes one `LanceVectorRecordStore` so both `memoryStore` and `qdrantService` share a single Lance connection when Qdrant is unavailable.
- Embedding pipeline (`embedding/`): `service.ts` (`EmbeddingService`) dispatches to providers (`providers.ts`) chosen by `EMBEDDING_PROVIDER` / env (`openai` | `tei` | `fastembed`), with `audit.ts`, `health.ts`, `lazy-probe.ts`, and `provider-audit.ts` wrapping calls for anomaly detection, health checks, dimension probing, and audit logging.
- Memory persistence (`memory/` + `qdrant/`): `memory/store.ts` defines the adapter contract; `qdrant/memory-store.ts` implements it over Qdrant collections; `qdrant/` splits concerns into `connection.ts`, `initialization.ts`, `search.ts`, `memory-retrieval.ts`, `memory-updates.ts`, `protocol.ts`, `quality.ts`, `resources.ts`, `reward-propagation.ts`, `snapshots.ts`.
- Vector records (`vector-store/`): abstracts LanceDB behind `IVectorRecordStore` / `IExecutionTraceStore` interfaces, with `lancedb/` containing schema, reads, writes, mutations, search, and artifact helpers.
- Metrics (`metrics/`): per-domain metric modules (`agent-metrics.ts`, `embedding-metrics.ts`, `memory-metrics.ts`, `qdrant-metrics.ts`, etc.) register with `registry.ts` and are consumed by services to emit counters/histograms tagged with `tenant_id`.
- Cross-cutting utilities: `id-generator.ts`, `code-block-processor.ts`, `adapter-layer-count.ts`, `adapter-navigation.ts`, `forward-runtime-store.ts`, `oidc-state-store.ts`, `proof-of-work-store.ts`, `reward-evals.ts`, `reward-metrics.ts`, `stats/` (scoring/bonuses/healer/model-stats).

Dependency direction is inward: consumers depend only on facade singletons and interfaces; concrete backends are never imported directly by callers.
