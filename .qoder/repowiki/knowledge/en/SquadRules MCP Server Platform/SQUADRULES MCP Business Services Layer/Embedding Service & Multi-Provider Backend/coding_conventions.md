- Each provider implementation (`postEmbeddingsOpenAI`, `postEmbeddingsTEI`, `postEmbeddingsFastEmbed`) normalizes input to `string[]`, records `inputCharLength`, calls `setResolvedEmbeddingDimension` with the first response's vector length, and emits a `auditProviderCall` entry with `status: 'success' | 'error'`.
- HTTP-based providers wrap their request loop in a shared retry strategy using `computeBackoffMs` (exponential backoff + random jitter), `computeRetryDelayMs` (honors `Retry-After` / `retry-after-ms` headers capped by `EMBEDDING_RETRY_AFTER_CAP_MS`), and a per-call `computeDeadline()` budget checked via `isBudgetExceeded`.
- Every successful or failed embedding path increments both `embeddingRequests.inc` and `embeddingErrors.inc` from `../metrics/embedding-metrics.js` with `{ provider, tenant_id }` labels, and logs via `logEmbeddingAuditSuccess` / `logEmbeddingAuditError` from `audit.ts`.
- Anomaly detection is performed centrally in `detectEmbeddingAnomalies`, which flags high latency, out-of-range vector norms, and dimension mismatches against the expected dimension resolved at startup.
- Configuration values are imported from `../../config.js` rather than read directly from `process.env`, keeping environment access centralized.
