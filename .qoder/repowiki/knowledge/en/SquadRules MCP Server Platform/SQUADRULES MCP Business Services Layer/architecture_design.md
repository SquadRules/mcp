Children compose a layered pipeline: `embedding_service` produces vectors consumed by `memory_store`, which persists Markdown adapters into Qdrant with BM25+vector hybrid search; `qdrant_client` is the shared database client used by both memory and the higher-level `vector_store` layer (which also exposes an embedded LanceDB adapter for the same contract). Cross-cutting concerns are centralized in `metrics_registry` (Prometheus counters/histograms per domain) and `stats_scoring` (quality/bonus computation persisted via the key-value store). The top-level files in `src/services/` (`key-value-store-factory.ts`, `redis-cache.ts`, `memory-store.ts`) provide the backend selection: Redis when configured, otherwise an in-process `MemoryStore`; this same pattern applies to vector stores (Qdrant vs. embedded LanceDB). All services read tenant/request context from `utils/tenant-context.js` and log through `utils/structured-logger.js`, keeping the HTTP layer (`src/http/`) and tools layer (`src/tools/`) free of persistence details.
