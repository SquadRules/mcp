Two backend-agnostic ports define the module boundary: `IVectorRecordStore` (vector-bearing memory, adapter chains, artifacts, slug resolution, scroll/admin) and `IExecutionTraceStore` (execution lifecycle, trace append, reward attachment, training-pair export). Both are implemented by a single embedded LanceDB adapter under `lancedb/`, allowing the same instance to back both the DI-injected `memoryStore` and the legacy `qdrantService` facade via `embedded-store-singleton.ts`. The Lance adapter is layered internally: `LanceVectorRecordStore` is the port-facing facade delegating to five sub-engines (`LanceRecordEngine`, `LanceRecordReader`, `LanceRecordMutator`, `LanceRecordSearch`, `LanceRecordWriter`) plus `LanceExecutionTraceStore` for non-vector traces. Cross-cutting concerns live at the module root: `lancedb-connection.ts` lazily imports `@lancedb/lancedb` and opens a strong-consistency connection (`readConsistencyInterval: 0`) against a per-user directory; `commit-retry.ts` wraps all writes in bounded exponential-backoff retry keyed on conflict-message detection. Domain shapes in `types.ts` (Memory, LayerRecord, StoredExecutionTrace, TrainingPair) are deliberately free of any backend client import so ports stay neutral.
