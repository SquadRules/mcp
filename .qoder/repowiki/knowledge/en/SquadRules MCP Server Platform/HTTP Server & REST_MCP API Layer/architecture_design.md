The module is an Express application assembled in `http-server.ts` by composing small `setupXxxRoute(app, ...)` modules. The bootstrap order is deliberate: middleware (`configureMiddleware`, `authMiddleware`) → well-known/CORS → protected route groups (`/api/*`, `/mcp`, `/ui`) → static UI → global error handlers. Route registration is centralized in `http-api-routes.ts`, which wires each feature file (`http-api-train-raw.ts`, `http-api-begin.ts`, `http-api-me.ts`, etc.) to a path under `/api`. Cross-cutting concerns are isolated: `http-auth-middleware.ts` handles session cookies (HMAC-signed) and Bearer/OIDC token validation with `WWW-Authenticate` responses; `http-error-handlers.ts` provides a single global Express error handler plus 404 catch-all; `http-server-startup.ts` wraps `app.listen` with EADDRINUSE handling. Dependencies on business logic (`MemoryQdrantStore`, `QdrantService`) and config (`../config.js`) are injected via function parameters rather than imported at module scope, keeping route files testable. Auth state is attached as `req.auth` / `req.spaceContext` for downstream handlers.
